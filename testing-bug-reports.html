PRIVATE TESTING

TURN A PROBLEM INTO A USEFUL REPORT

A clear report gives Limelight the exact scene, actions, and diagnostics needed to reproduce a problem. The built-in report creator collects the technical context while you explain what happened.

Before You Test

Start from a known state so the result describes one issue instead of several overlapping changes.

  • Use the newest Early Access build available.
  • Confirm Limelight accepts the connected Dead as Disco build.
  • Write down the mod name and selected loader mode.
  • Wait for loading screens and Limelight indicators to finish before switching.
  • Test one change at a time whenever possible.
DO NOT REPEAT AN UNSAFE ACTION

If Dead as Disco freezes, closes, creates a crash dump, or Limelight marks the session as interrupted, stop testing that action. Preserve the evidence and restart before trying anything else.

Create a Private Test Report

Limelight already has a guided report creator. Open Settings, choose Support, then select Create Private Test Report.

01

Name the issue

Use a short title that describes the broken action and result, such as "Fuji textures turn black after the second X19 switch".

02

Choose the area and outcome

Select the closest Limelight feature, then record whether there was no crash, a dump, a closed application, or a freeze.

03

Describe the exact sequence

List each click, key press, loader selection, mod selection, and game location in order. Include the result you expected and the result you actually saw.

04

Add useful evidence

Add screenshots, logs, or crash dumps that belong to this issue. Limelight accepts up to ten selected files.

05

Create and review the ZIP

Select Create Report ZIP, choose where to save it, and review the contents before sending it to the person coordinating the private test.

What a Good Report Looks Like

Someone who did not watch the test should be able to follow your notes and reach the same result.

ISSUE TITLE Fuji textures turn black after the second X19 switch STEPS TO REPRODUCE 1. Launch Dead as Disco through Limelight with X19 LLoader. 2. Enter the bar and wait until the level is fully visible. 3. Switch from Haru Urara to Fuji Kiseki. 4. Wait for the Limelight indicator to disappear. 5. Switch to Manhattan Cafe, then back to Fuji Kiseki. EXPECTED RESULT Fuji Kiseki loads with her mesh, materials, and textures. WHAT ACTUALLY HAPPENED The mesh changed, but the body and hair appeared black.
SMALL DETAILS ARE USEFUL

Include whether the problem happened on first launch, after a level change, only in X19 mode, or only with a particular ordering of mods.

Evidence You Can Include

The report creator accepts common images, crash dumps, and text-based diagnostic files. It renames attachments inside the ZIP so their original folder paths are not used as archive names.

  • Images: PNG, JPG, JPEG, and WEBP
  • Crash dumps: DMP
  • Logs and text: LOG and TXT
  • Structured text: JSON, XML, and CSV
  • Configuration files: INI and CFG

Choose the smallest set of files that proves the issue. One clear screenshot and the matching log are more useful than a folder full of unrelated files.

REVIEW BINARY EVIDENCE

Limelight sanitises supported text attachments, but screenshots and crash dumps are binary files and may contain technical or personal data. Include them only when you are comfortable sharing them with the tester.

What Limelight Adds Automatically

You do not need to copy system details by hand. The generated report records the context Limelight already knows about the current test.

  • Limelight, Windows, and .NET versions
  • Selected Live Loader mode
  • Current and peak Limelight memory use
  • Connected game and compatibility status
  • Installed and active mod information
  • Live Loader installation and bridge status
  • Live-session switches, containers, staging, and recovery details
  • Recent UE4SS events when they can be read

The generated text replaces saved user names, installation paths, and the stored Nexus API key with private labels.

Privacy and Sending the Report

Creating a report only saves a ZIP on your computer. Limelight does not upload it automatically. You decide whether to send it and which evidence to include.

  1. Open the generated ZIP and confirm it belongs to the issue you tested.
  2. Review any screenshot or crash dump you selected.
  3. Send the complete ZIP through the private testing channel you were given.
  4. Create a separate report for a separate problem.

Read the Privacy guide for a fuller explanation of Limelight's local data and report handling.

Describe the Impact Clearly

  • Blocker: Dead as Disco or Limelight cannot be started, or user data may be lost.
  • High: A repeatable hard freeze, application close, or crash dump interrupts normal use.
  • Medium: A feature fails, but the game and manager remain usable.
  • Low: A visual, wording, spacing, or polish issue does not block the feature.

The outcome selected in Limelight is the most important signal. Add a severity word to your title only when it makes the report easier to triage.

Try Safe Recovery First

If you want to keep testing after saving the report, follow the recovery checklist before starting a fresh session.
