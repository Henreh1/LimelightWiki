DOCUMENTATION / LIMELIGHTMP
EXPERIMENTAL ONLINE CO-OP

SHARE THE DANCE FLOOR

LimelightMP is an early two-player co-op prototype built into Limelight. The host plays Charlie, a friend joins as Chuckles, and both computers run and render their own copy of Dead as Disco.

Experimental Means Experimental

EXPECT BUGS, DISCONNECTS, AND INCOMPLETE FEATURES

LimelightMP is not finished multiplayer support and is not a replacement for an official online mode. Test it only with a friend who understands that sessions may need to be restarted.

The current prototype combines Dead as Disco's working couch co-op players with a private online input relay and Unreal networking. Gameplay remains host-authoritative while the joining player renders the replicated session locally. It is not video streaming or remote desktop play.

Before You Start

  • Both players need the same Limelight test build.
  • Both players need the same supported Dead as Disco build.
  • Both players should close the game before choosing Host or Join.
  • Both computers need Tailscale installed, connected, and permitted to reach each other.
  • Keep Limelight open for the whole session.
  • Use one host and one joining player only.
USE A PRIVATE TAILSCALE ROUTE

Share the host computer with the friend who is testing, not an entire network when a single device share is available. Limelight's friend code contains connection information, so send it privately and redact it from public screenshots.

Host a Session

  1. Open Limelight and select LimelightMP.
  2. Confirm the setup check is ready.
  3. Select Host and Launch.
  4. Copy the complete short friend code and send it privately.
  5. Enter the Dive Bar after Dead as Disco opens.
  6. Press Ctrl+Shift+F5 once to begin hosting.
  7. Wait for Limelight to report that the host is listening.

The host controls Charlie and remains responsible for level and song selection. Do not start travelling while the joining player is still connecting.

Join a Friend

  1. Open the same Limelight build and select LimelightMP.
  2. Paste the host's complete friend code.
  3. Select Join and Launch.
  4. Leave Limelight open while the local game starts.
  5. Wait until Limelight reports that the host welcomed the client.
  6. Confirm that Chuckles is visible and responds before the host changes level.

The joining computer renders its own game. Normal internet latency still applies, but the picture is not being streamed from the host's screen.

Useful Session Controls

  • Ctrl+Shift+F5 starts hosting from the Dive Bar.
  • Ctrl+Shift+F10 teleports Chuckles beside Charlie if a transition separates the players.
  • The host should select levels, modes, and songs only after both players are ready.
  • Close both games before changing multiplayer roles or switching builds.

Known Limitations in 0.1.0

The following systems are implemented but remain under active verification. A successful test in one arena does not yet guarantee the same result in every story segment.

  • HUD visibility can change after map or sub-level transitions.
  • Client skill and appearance menus do not yet behave consistently.
  • Music may start late or fail to recover in some levels.
  • Beat timing can differ from the vanilla single-player presentation.
  • The client may see a black screen during a sub-level transition.
  • Client movement can temporarily use the wrong camera direction.
  • Replicated movement, attacks, animations, particles, and warning effects may appear late or fail to play.
  • Level travel may reconnect the client instead of remaining seamless.
  • Live-switched character models may not appear identically for both players.
DO NOT TREAT A WORKAROUND AS A FIX

If restarting, teleporting, or reopening a menu makes an issue disappear, include that detail in the report. It helps distinguish a presentation recovery from a real multiplayer correction.

Report One Session Clearly

When a test fails, avoid running many different experiments before collecting evidence. Close both games normally, preserve the newest crash dump if one was created, and create a Limelight diagnostic report.

  • Say which computer hosted and which joined.
  • Name the level, mode, and song.
  • Describe the last action that worked and the first action that failed.
  • State whether the problem affected the host, client, or both.
  • Include whether a controller or mouse and keyboard was used.
  • Attach the newest crash dump when a fatal error appears.
